# 零界 ZeroGrid — 全生态发展思路详解

## 一、先搞懂一个问题：ZeroGrid 到底是什么？

很多人第一眼看：哦，又一个聊天软件。

**不对。**

ZeroGrid 的定位是 **Web3 原生去中心化协议层**。聊天只是它上面跑的第一个应用。

| 类比 | 说明 |
|------|------|
| **HTTP 是协议，浏览器是应用** | ZeroGrid 是协议，ZeroChat 是应用 |
| **TCP/IP 是协议，微信是应用** | 但微信是中心化的，ZeroGrid 不是 |
| **以太坊是协议，Uniswap 是应用** | ZeroGrid 是通信协议，ZeroChat/ZeroPay/ZeroStore 是应用 |

**一句话**：ZeroGrid 要做的是 Web3 时代人与人之间通信、支付、存储的底层协议，跟 TCP/IP 一样是谁都可以用、没人能关掉的基础设施。

## 二、为什么这个事值得做？（市场痛点）

现在主流的通信工具全都有三个致命问题：

### 问题 1：中心化审查

WhatsApp / Telegram / 微信 — 服务器在某家公司手里。你的聊天记录他们能看（或被迫交给政府），你的账号随时可以封禁，你的数据说删就删。

ZeroGrid 的解法：**没有中心服务器**，每个用户自己就是节点，消息 P2P 直传。

### 问题 2：安全和身份分离

现在的互联网：注册微信需要手机号绑定，你的身份是微信"施舍"给你的。没了手机号，你的社交关系全部丢失。

Signal 有 E2EE 但账号还是绑手机号。Telegram 有加密但只有一对一，群聊是明文。WhatsApp 有加密但 Facebook 有后门。

ZeroGrid 的解法：**ZeroID = BIP39 助记词 → 你自己生成的身份**，跟手机号、邮箱、国籍完全无关。12 个单词，你走到哪儿身份跟到哪，没人能剥夺。

### 问题 3：通信、支付、身份各自割裂

现在你需要：微信聊天（中国）+ Telegram 聊天（海外）+ MetaMask 钱包 + Telegram 内置钱包（仅 TON）+ iCloud/Google Drive 存文件 + Twitter/朋友圈社交 — 五个 APP，五套身份，五家公司拿着你的数据。

ZeroGrid 的解法：**一个 ZeroID 贯穿全部**。聊天、转账、存文件、发朋友圈，全在一个协议上，同一个身份。

### 第 1-2 层：传输层 + 网络层 — 消息怎么传？

核心原则：能直连就不中转，必须中转就加密中转。

#### 四种通信场景

| 场景 | 方式 | 延迟 | 成本 |
|------|------|:---:|:---:|
| 两人同网在线 | WebRTC P2P 直连 | ~10ms | 零 |
| 不同网络（NAT 后） | ZeroNode 中继（加密） | ~50ms | 微量 ZERO |
| 完全离线（野外/灾难） | BLE 蓝牙 Mesh | ~200ms | 零 |
| 一端离线 | DASN 存储 → 上线拉取 | 秒级 | 微量 ZERO |

#### 网络层核心组件

| 组件 | 作用 | 类比 |
|------|------|------|
| **libp2p** | P2P 网络框架 | 操作系统的"网络栈" |
| **Kademlia DHT** | 分布式哈希表，找节点 | 分布式电话本 |
| **Gossipsub** | 消息广播协议 | 村里口口相传 |
| **AutoNAT** | 自动判断 NAT 类型 | 自动决定是否中转 |
| **BLE Mesh** | 离线蓝牙通信 | 对讲机，无需互联网 |
| **ZeroNode** | 激励中继节点 | 快递中转站，赚钱 |

### 第 3-4 层：安全层 + 存储层 — 怎么保证没人偷看？

#### 端到端加密（E2EE）完整流程

```
第一步：身份建立
    12 个随机助记词
        ↓ PBKDF2 (2048 轮)
    64 字节种子
        ↓ HKDF 派生
    P-256 ECDSA 密钥对
        ↓ SHA256 编码
    ZeroID: ZA7B3F8K2M

第二步：建立会话（X3DH 密钥协商）
    Alice 私钥 + Bob 公钥
        → ECDH → 共享密钥
        → HKDF → root_key

第三步：持续加密（Double Ratchet 双棘轮）
    每条消息发出后，密钥自动轮换：
        root_key → HKDF → sending_chain_key
        sending_chain_key → HKDF → message_key
    
    消息 1：key_1 加密
    消息 2：key_2 加密（自动演进，无法回推）
    消息 3：key_3 加密
    
    前向安全性：就算拿到 key_3，也解不开消息 1 和 2

第四步：AEAD 加密
    message_key (32 字节) + 随机 nonce (12 字节)
    → ChaCha20-Poly1305 → 密文 + MAC 校验码
```

#### DASN 存储层

传统云存储：文件上传到阿里云 → 阿里云能看、能删、能改。

DASN：文件 → SHA256 → CID `z0a1b2c3...` → 切片分发到多个 ZeroNode → 随时用 CID 拉回。

特性：内容不可篡改（改了就校验不通过）、自动冗余（多个节点各存一份）、不可删除（无中心服务器）、可选加密存储。

### 第 5 层：身份层 — 你的数字主权

#### ZeroID 才是核心资产

传统身份：微信账号 = 腾讯"借"给你的，封号 → 社交关系归零。

ZeroID：12 个英文单词 = 永久身份，存在脑子里或者纸上，没人能封、能删、能收回。

ZeroID 拥有的：你的所有社交关系、钱包余额（BTC/ETH/USDT 等）、DASN 存储文件、DID 身份证书、ZERO 代币。

#### ZeroDNS 域名系统

原始 ZeroID `ZA7B3F8K2M` 不好记。ZeroDNS 让你拍卖/注册 `.zero` 域名：`alice.zero` → 映射到你的 ZeroID。

用途：聊天搜 `alice.zero` 就能加好友、向 `alice.zero` 转账、个人主页 `alice.zero`。域名是 NFT，可转让交易，好名字会越来越贵。

### 第 6 层：经济层 — 谁出钱跑这个网络？

核心问题：P2P 网络需要中继节点，谁愿意搭服务器白干活？答案：给钱 — **ZERO 代币**。

#### ZeroNode 激励模型

| 角色 | 做什么 | 赚什么 |
|------|--------|--------|
| 中继节点 | 转发加密消息 | ZERO |
| 存储节点 | DASN 存文件 | ZERO |
| 验证节点 | ZeroChain 区块验证 | ZERO |
| DHT 节点 | 提供路由查询 | ZERO（少量） |
| 轻节点 | 普通用户 | 消耗 ZERO（微量） |

#### ZERO 代币经济

- 总量上限：10 亿 ZERO
- 通胀率：每年 2%，逐渐递减 → 0%
- 分配：40% 节点激励挖矿（20 年释放）、20% 生态基金（开发者补贴）、15% 创始团队（4 年锁仓）、15% 社区空投、10% DAO 金库

#### 核心飞轮（增长逻辑）

```
用户用 ZeroChat（加密、免费、不封号）
    ↓
用户多了 → 需要更多中继节点
    ↓
有人搭 ZeroNode → 挖 ZERO 代币赚钱
    ↓
ZERO 可用于域名注册、支付手续费折扣
    ↓
ZERO 有价值 → 更多人挖 → 网络更稳定 → 更多用户来
    ↓
回到第一步，转起来了 ♻️
```

飞轮组合了三种机制：消息中继挖矿 + 存储挖矿 + 用户增长 → ZERO 价值提升。类似比特币（挖矿安全飞轮）、Filecoin（存储挖矿飞轮）、Helium（网络覆盖飞轮）三者合一。

### 第 7 层：应用层 — 杀手级应用全家桶

#### ZeroChat — 加密通信（已落地基础版）

基础功能：文本/图片/语音/文件/位置消息、一对一 E2EE、阅后即焚、BLE 离线通信、4 套主题模版。

待开发：群聊 E2EE（MLS 协议）、音视频通话（WebRTC + E2EE）、消息状态回执、频道/广播。

#### ZeroPay — 聊天即支付

聊天框直接转账：`/pay 200 usdt` → 确认 → 钱直接从 Alice 钱包到 Bob 钱包。群收款、智能合约担保交易。兼容 EVM 链上所有资产，不依赖任何交易所或第三方托管。

#### ZeroStore — 去中心化加密云存储

文件通过 DASN 协议切片分发，SHA256 CID 寻址，支付少量 ZERO 给存储节点。文件永不丢失（多节点冗余）、不可篡改（CID 校验）、可选加密存储、零审查。

#### ZeroFeed — 去中心化信息流

类似 Twitter + 朋友圈，但：没有算法推荐（你的时间线你做主）、关注列表存 ZeroID（跟平台无关）、内容存 DASN（删不掉）、零广告。

#### ZeroMarket — P2P 去中心化集市

挂单商品上链，智能合约托管付款，纠纷由 ZeroDAO 仲裁。没有平台抽成、交易双方直接加密通信、资金合约托管不怕跑路。

#### ZeroDAO — 协议治理

ZERO 持有者投票决定：协议参数调整（消息中继费用等）、生态基金拨款、域名规则、仲裁纠纷。1 ZERO = 1 票，支持委托投票。
